# Co-op Library — Price History Setup

This site is hosted on GitHub Pages and no longer asks visitors for an API
key. Instead, price data is fetched **once ahead of time** (by a scheduled
GitHub Actions workflow, not a build step — Pages doesn't have one) and
served as a static JSON file. Here's how it fits together:

```
games.json          <- you edit this to add/remove games (must match appids used in coop-library.html)
fetch-prices.js      <- reads games.json, calls IsThereAnyDeal, writes prices.json
prices.json           <- generated file, loaded by the page (never edit by hand)
game-info.json        <- per-game detail pages: theme, gallery, i18n (EN/FR), platform data — you hand-edit most of this
fetch-game-info.js    <- refreshes each game's `heroImage` field in game-info.json from the Steam appdetails API (never touches `gallery`)
fetch-spec-requirements.js <- refreshes each game's `canYouRunIt` block in game-info.json (min/rec PC requirements, parsed against hardware-tiers.js) for the "Can You Run It?" section on info.html
coop-library.html      <- the main library page (grid of games, filters)
info.html               <- one reusable game-details page for every game, driven by game-info.json (?game=<appid>)
price-history.html      <- the chart page, deep-linked as price-history.html?appid=NNNN
.github/workflows/refresh-data.yml <- runs fetch-prices.js + fetch-game-info.js + fetch-spec-requirements.js daily and commits any changes, which is what triggers a GitHub Pages redeploy
```

`coop-library.html`'s "📈 Price history" link on each card points to
`price-history.html?appid=<that game's Steam appid>`, which reads
`games.json` + `prices.json` to find the matching game and render its chart.
If you want `coop-library.html` to be the page visitors land on first,
rename it to `index.html` (or add a `404.html`/redirect page — GitHub
Pages has no server-side redirect config like Netlify's `_redirects`).

## Game details pages

There's one HTML file for every game's detail page: `info.html`. It reads
`?game=<appid>` from the URL and pulls that game's entry out of
`game-info.json` — theme colors/fonts, hero image, gallery, platform info,
English + French copy, all of it. To add a details page for a new game, add
an entry to `game-info.json` keyed by its Steam appid (copy an existing
entry as a starting point) and link to `info.html?game=<appid>`. No new
HTML file needed.

`gallery` is fully hand-typed — add the screenshot URLs yourself and they
stay exactly as you left them. The one thing that's machine-generated is
`heroImage`: `fetch-game-info.js` calls Steam's public appdetails API for
any appid in `game-info.json` whose `heroImage` is still empty, and fills
it in with that game's first real screenshot. It runs automatically as
part of the daily GitHub Actions workflow (see
`.github/workflows/refresh-data.yml`), same as the price fetch.
It never touches theme, i18n, platform data, or `gallery` — and it skips
any game that already has a `heroImage` set, so once you've picked one
you like it's never overwritten.

To test it locally: `node fetch-game-info.js` (no API key needed, unlike
the price fetch — Steam's appdetails endpoint is public).

## "Can You Run It?"

The "Can You Run It?" tab on `info.html` compares a visitor's hardware
against a game's minimum/recommended PC requirements. That data lives in
each game's `canYouRunIt` block in `game-info.json`, and it's entirely
machine-generated by `fetch-spec-requirements.js` — don't hand-edit it.

For every game in `game-info.json`, the script pulls Steam's minimum and
recommended requirements text, matches the listed CPU/GPU against
`hardware-tiers.js`, and writes back `requirements.minimum` /
`requirements.recommended` (parsed CPU/GPU/RAM/storage, used client-side
to compare visitor specs with no further Steam calls) plus a precomputed
`mySpecs` result. Like `fetch-game-info.js`, it needs no API key — Steam's
appdetails endpoint is public — and it runs automatically as part of the
daily GitHub Actions workflow (see `.github/workflows/refresh-data.yml`).

Matching isn't perfect: Steam's requirement text is publisher-written free
text, and `hardware-tiers.js` only covers recent/mid-range-and-up parts, so
older minimum-spec CPUs/GPUs often come back unmatched. That's expected —
the script logs every unmatched component so you can sanity-check or
hand-correct specific games afterward.

To test it locally: `node fetch-spec-requirements.js`.

## One-time setup

1. **Get an ITAD API key**
   Register a small app at https://isthereanydeal.com/apps/my/ (no approval
   needed) and copy the API key it gives you.

2. **Add the key as a repository secret (not to the code!)**
   In your GitHub repo: Settings → Secrets and variables → Actions →
   New repository secret:
   - Name: `ITAD_API_KEY`, Value: your key

3. **Turn on GitHub Pages**
   Settings → Pages → Source: **Deploy from a branch** → pick `main` and
   `/ (root)`. GitHub Pages just serves whatever is committed to that
   branch — there's no separate build step to configure.

4. **Enable the workflow**
   `.github/workflows/refresh-data.yml` is already in the repo and needs
   no further setup. As long as Actions are enabled for the repo (they are
   by default), it will start running on its own schedule.

That's it. From now on:
- The workflow runs once a day (04:00 UTC by default — edit the `cron`
  line in `refresh-data.yml` if you want a different time), regenerating
  `prices.json` and `game-info.json` and committing the result straight to
  `main`. That commit is what GitHub Pages picks up and redeploys — there's
  no build hook to wire up.
- It also runs automatically whenever `games.json` changes, so a newly
  added game gets its price history without waiting for the next scheduled
  run.
- You can trigger a refresh manually any time from the repo's Actions tab
  → "Refresh price & game data" → Run workflow.

## Theme switcher

Both pages include a small circle-button switcher (🌙 / ☀️ / 🖼️) powered by `theme.js`:

- **Dark** and **Light** swap the color palette instantly.
- **Custom** lets a visitor upload their own photo as a wallpaper. The image is resized/compressed in the browser and saved in `localStorage`, so it stays applied across pages and future visits **on that browser only** — it's not uploaded anywhere or shared with other visitors.
- Clicking 🖼️ again while it's already active lets you swap the photo; the ✕ button that appears next to it removes the wallpaper and reverts to the last dark/light theme.

To add the switcher to a new page, include the script and an empty container:

```html
<script src="theme.js"></script>
...
<div class="theme-switch" id="themeSwitcher"></div>
```

and copy the `.theme-switch` / `.theme-btn` / `.theme-remove-btn` CSS rules from `coop-library.html` or `price-history.html`.

## Adding a game

Just edit `games.json` and add an entry with the Steam appid:

```json
{ "appid": 570, "title": "Dota 2", "players": "2-10" }
```

Commit + push. The daily workflow (or the one that auto-runs on changes
to `games.json`, see above) will fetch its price history automatically —
no manual redeploy needed.

## Testing locally

You'll need Node 18+ (for built-in `fetch`). From this folder:

```bash
ITAD_API_KEY=your_key_here node fetch-prices.js
```

Then serve the folder with any static server (double-clicking the HTML
file won't work — browsers block API-style fetches from `file://` pages,
even for local JSON in some browsers). For example:

```bash
npx serve .
```
